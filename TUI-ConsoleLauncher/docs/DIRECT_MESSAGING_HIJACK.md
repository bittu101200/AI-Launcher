# Technical Specification: Direct Messaging Hijack via RemoteInput

This document explains how the AI Launcher implements background messaging for third-party apps (WhatsApp, Telegram, etc.) without using official APIs, SDKs, or root access.

## 1. Core Concept: RemoteInput "Replay"
Android's `Notification.Action` API allows apps to include a `RemoteInput` for "Quick Replies". This mechanism is designed for WearOS and Android Auto, but it can be utilized by any app with `NotificationListenerService` permissions to act as a "ghost" sender.

### The Hijack Pipeline
1.  **Detection:** `NotificationService` intercepts a `StatusBarNotification` (SBN).
2.  **Extraction:** `ReplyManager` scans the SBN for a `WearableExtender` or `Notification.Action` that contains `RemoteInput` objects.
3.  **Caching:** The launcher stores three critical components:
    *   **PendingIntent:** The unique "token" that WhatsApp uses to identify the specific conversation.
    *   **RemoteInput Key:** The specific field name (e.g., `"direct_reply"`) the app expects for the text body.
    *   **Contact Identity:** The resolved notification title (e.g., "John Doe").

## 2. Multi-Contact Resolution
Previously, the system only stored the last received notification. The current implementation uses a `HashSet` of `NotificationWear` objects with a custom `equals()` and `hashCode()` override:

```java
// Logic implemented in NotificationWear.java
public boolean equals(Object obj) {
    // Two notification tokens are considered "same" if:
    // 1. They belong to the same package (com.whatsapp)
    // 2. They have the identical contact title (John Doe)
}
```

This allows the AI to distinguish between "Reply to John" and "Reply to Sarah" by looking up the specific `PendingIntent` mapped to that name in the cache.

## 3. Background Execution Logic
When a command like `reply -to WhatsApp "Hello"` or an AI tool call `system.send_app_message` is issued:

1.  **Bundle Preparation:** A new `Bundle` is created.
2.  **Input Mapping:** The message text is inserted into the bundle using the key found during extraction.
    ```java
    RemoteInput.addResultsToIntent(remoteInputs, intent, resultsBundle);
    ```
3.  **Intent Firing:** The `PendingIntent` is sent. Android treats this as if the user manually interacted with the notification's "Reply" button.

## 4. Deep-Link Fallback
When no notification exists in the cache (and thus no `PendingIntent` is available), the system falls back to **Intent Deep Linking**.

For WhatsApp, the launcher constructs a URI:
`https://wa.me/[phone_number]?text=[encoded_message]`

This triggers the `ACTION_VIEW` intent, which the WhatsApp Android Manifest is registered to handle, opening the specific chat activity with the text already populated in the input field.

## 5. Security & Limitations
*   **Permissions:** Requires `NotificationListenerService` (Notification Access).
*   **Ephemeral Nature:** Background sending only works as long as the app has "seen" a notification from that contact since the last boot/cache clear.
*   **Privacy:** No credentials are ever stored; only the session-based `PendingIntent` generated by the target app is used.
